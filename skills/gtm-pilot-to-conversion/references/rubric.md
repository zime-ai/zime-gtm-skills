# Pilot-to-conversion rubric

Eight dimensions covering whether a pilot or POC is on track to convert,
not just running.

## 1. Plan & success criteria agreed upfront

Was there a specific, mutually agreed plan for what the pilot would test
and what "success" means, established before it started — or did the
pilot begin without a clear finish line?

## 2. Technical integration readiness

Is the pilot actually integrated with the systems it needs to touch, or
running in a way that won't reflect real production conditions?

## 3. Admin & security readiness

Are access, permissions, and any security requirements sorted, or is the
pilot stalling on internal IT/security process?

## 4. Setup experience so far

Did the people running the pilot get a genuinely smooth start, or are they
still fighting basic setup partway through?

## 5. User attendance & engagement

Are the intended users actually using the pilot regularly, or has
engagement dropped off since kickoff? Fading usage mid-pilot is one of the
strongest early signals a conversion won't happen.

## 6. Feature-level feedback captured

Is specific feedback being gathered on what's working and what isn't, or
is the check-in staying at a vague "going fine" level?

## 7. Results measured against criteria

Is there actual evidence — a number, an observed outcome — being compared
against the criteria set in step 1, or is "success" still undefined this
far in?

## 8. Clear conversion path

Did the call produce a specific next step toward a decision — a defined
end date, a stakeholder review, a proposal — or is the pilot open-ended
with no path to closing?

## Reads-well-too check

Sanity-check against a pilot you know converted well. If it still comes
back mostly Missed, loosen the read before reporting.
